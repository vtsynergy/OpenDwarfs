# CUDA tree

CUDA translations of the 14 OpenDwarfs applications, written from the current `../opencl/` sources (OpenCL is the reference).
Target: NVIDIA H100 (`sm_90`), nvcc 12.9.86 from NVIDIA HPC SDK 25.7. Same algorithms, command lines, validators,
host/device transfer pattern and timer (`../common/dwarf_timer.h`, `model=cuda`). Design details, differences and the
timed-region audit are in `NOTES.md`.

## Build and run

    source ../toolchains/env.sh
    make -C <app dir> build                       # into <app dir>/build
    make -C <app dir> run GPU_INDEX=1 RUN_ARGS="..."
    GPU_INDEX=1 ./run_all.sh [--size small|medium] [--repeats N] [--only a,b] [--outdir DIR]

Inputs are read from `../opencl/test/`. `crc` and `spmv` inputs are generated by `createcrc` / `createcsr` in this tree
(with `-R`; the files checked were identical to `../data/inputs/`). `gem` runs on private copies of its inputs.
`make clean` only prints the directory to delete; it removes nothing.

| Variable | Default | Meaning |
|---|---|---|
| `CUDACC` | HPC SDK `nvcc` | any nvcc-compatible driver |
| `BUILD_DIR` | `build` | use a separate one per compiler, e.g. `build-scale` |
| `GPU_ARCH_SM` | 90 | target architecture |
| `FPFLAGS` | `-prec-div=false -prec-sqrt=false` | OpenCL-like fp32 divide/sqrt; `FPFLAGS=` gives nvcc defaults |

SCALE (not installed here, see `NOTES.md`) would be selected with
`make CUDACC=<prefix>/targets/<target>/bin/nvcc BUILD_DIR=build-scale`. This is untested; SCALE may need `FPFLAGS=` if it
does not accept the two nvcc floating-point options (not checked).

## Results (2026-11-25, H100 NVL, driver 620.70.06)

`run_all.sh`, fresh build (`BUILD_DIR=build-runall`): **14/14 PASS at `--size small` and 14/14 PASS at `--size medium`**;
small also 14/14 PASS with `DWARF_REPEATS=3 DWARF_WARMUP=1`. PASS there means the application's own validator only.
For `kmeans`, `cfd`, `gem`, `swat` and `tdm` that validator is a weak sanity check (finite values, positive score, work
done), so the comparison with OpenCL below is the real evidence.

Comparison with NVIDIA OpenCL: every device-to-host copy of both programs was captured with an `LD_PRELOAD` shim (CUDA side
built with `-cudart=shared`, otherwise identical flags) and compared record by record. The shim lives in the translator's
scratch area, not in this repository.

| App | Sizes compared | Validator | Output vs OpenCL |
|---|---|---|---|
| lud | 256, 2048 | PASS | bitwise identical (needs CUDA-WA-01 and default `FPFLAGS`) |
| spmv | small, medium | PASS | bitwise identical |
| bfs | 4096, 65536 | PASS | bitwise identical, also `bfs_result.txt` |
| crc | small, medium | PASS | bitwise identical |
| nw | 1024, 4096 | PASS | bitwise identical, same traceback |
| srad | 512, 2048 | PASS | bitwise identical |
| cfd | 097K, 193K | PASS | not bitwise: 931 / 653 of the final values differ, max abs 7.2e-7 / 4.8e-7, relative L2 < 4e-9; `density.txt` identical |
| kmeans | 204800, 819200 | PASS | bitwise identical, same centroids and RMSE |
| nqueens | 12, 14 | PASS | bitwise identical |
| hmm | 60, 120 | PASS | bitwise identical (3004 copies each) |
| swat | 1K, 3K | PASS | bitwise identical, same alignment text |
| tdm | size50, size500 | PASS | bitwise identical, also `tdm-gpu-csw.txt` |
| gem | 1uwo_A, Mb.Hhelix.bondi | PASS | not bitwise: max abs 7.3e-5 / 5.7e-5, relative L2 2.6e-6 / 7.5e-6 |
| fft | --pts 1..7 (1-D) | PASS | not bitwise: relative L2 <= 1.2e-7, max abs <= 3.1e-5; same error against the double DFT; same launch sizes |

Why the three inexact apps are accepted: `cfd` and `fft` differences are at single-precision rounding level. `gem`
potentials are long single-precision sums and some nearly cancel (the printed maximum for 1uwo_A is 0.0826898 in OpenCL
and 0.0826589 in CUDA). Other floating-point settings tried for CUDA give a larger maximum gap to OpenCL (`-fmad=false`
3.7e-4, `-prec-div=true` 1.3e-4 on 1uwo_A), so the result is this sensitive to rounding choices; replacing `__expf` with
`expf` changed neither the count nor the maximum (that call is not reached with these arguments).
The exact source of the remaining `cfd`, `gem` and `fft` differences was not isolated. No performance was measured.
